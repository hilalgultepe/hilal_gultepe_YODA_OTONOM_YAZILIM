Repository: Yapılan projedeki tüm kodların, değişikliklerin kayıt altına alındığı klasör.
Commit: Yapılan değişiklikleri geçmişe kalıcı olarak kaydetme, her değişikliği adım adım kaydetme.
Branch: Ana projede (main) değişiklik yapmadan yeni özelliklerle burada denenir, daha sonrasında uygunsa ana projeye eklenir.
Stage: Yapılan değişikliklerin tamamı kalıcı olarak kaydedilmeden önce burada görürsünüz ve hangilerini kalıcı olarak kaydedeceğinizi belirlersiniz.
Merge: Farklı branchları birleştirmek için kullanılır.
Pull: Başka depodan kod ve değişiklikleri kendi bilgisayarına indirmek için kullanılır.
Push: Kendi bilgisayarından commitleri depoya yüklemek için kullanılır.

Takımlar neden Git ve GitHub kullanır?

1. Versiyon kontrolüne neden ihtiyaç duyulur?
   Git kullanılmadığı durumlarda hazırlanan dosyalarda karışıklık yaşanabilir. Yanlışlık yapıldığında geri almak mümkün olmayabilir. Bu gibi durumların yaşanmaması için kullanılır. Git hazırlanan projenin her adımını kayıt altına aldığı için sorunsuz hale geri dönmek mümkündür.
   
2. Git ile GitHub arasındaki fark
   Git bilgisayarda kullanılan kod değişikliklerini kayıt altına alan kontrol yazılımıdır. GitHub ise Git projelerinin saklandığı, kişilerin birlikte bir proje üzerinde çalışmasını sağlayan platformdur. Alternatif olarak GitLab, Bitbucket öne çıkan platformlar arasındadır.

3. Ekip çalışmasına katkıları
   Kişiler birbirlerinin kodlarına müdahale etmeden aynı anda aynı projede çalışabilirler, bunun için branchlar kullanılır. Pull Request, yapılan değişikliklerin ana projeye eklenmesi için diğer kişilerden onay istemesidir. Code Review ise yapılan değişikliğin ana projeye eklenmeden önce diğer kişiler tarafından incelenmesidir. Merge Conflict, farklı branchlardan yapılan değişikliğin çakışması sonucu geliştiricilerin kendilerinin seçim yapması durumudur.

4. GitHub'ın proje yönetimi özellikleri
   Issues: Her değişiklik talebini, yapılacak işleri listelemek için kullanılır.
   Projects: Yapılacak, yapılıyor, yapıldı gibi bölemlerle projenin sürecini resmeder.
   Actions: Kod yüklendiğinde otomatik kontrol edilmesini sağlar.

5. Öğrenci kulüpleri ve takımları için önemi
   Takımda üye değişikliği olsa dahi yapılan tüm çalışmalara erişim sağlanmasına yardımcı olur. Yeni üyelerin geçmiş çalışmaları incelemesi ve sistemin nasıl işlediğini öğrenmesini sağlar.

6. Otonom araç projesindeki yeri
   Farklı birimlerin ortak çalışmasını sağlar.

7. Dikkat edilmesi gerekenler
   Onay almadan yapılan değişikliklerin kalıcı olarak kaydedilmemesine dikkat edilmemelidir. Önlem olarak dokunulması istenilmeyen dosyaları [.gitignore] kullanarak koruma altına alabiliriz.
